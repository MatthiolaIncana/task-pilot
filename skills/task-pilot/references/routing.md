# Routing / 路由

## 目的

找到当前任务真正应遵循的流程，不建立平行流程。

## 路由顺序

1. 读取用户当前明确要求。
2. 识别用户是否明确指定某份工作流、Skill、文件或规则。
3. 识别当前项目是否已有稳定规则、已确认决策或专业流程。
4. 判断这些规则是否覆盖当前任务。
5. 覆盖：按该流程执行；Task Pilot 只补边界、状态、冲突和完成检查。
6. 不覆盖：仅对未覆盖部分使用 Task Pilot 通用规则。

## 不建立平行流程

如果一个专业工作流已经定义：阶段顺序、必做步骤、方案数量、验证方式、交付物或完成标准，Task Pilot 不得另外建立一套对应规则。

例如，专业工作流已经要求“先现状核实，再实现，再实机验收”，Task Pilot 的职责是确认这些阶段被真实执行，而不是再创建“Inspect → Execute → Verify”作为第二套独立流程。

## 部分覆盖

如果专业 Skill 只覆盖专业判断，不覆盖项目续接或最终交付：

- 专业判断交给专业 Skill；
- Task Pilot 只补未覆盖的状态、边界或完成检查；
- 不复制专业规则到 Task Pilot。

## 冲突处理

先判断是否真的冲突：不同规则可能处于不同层级或负责不同问题。

真正冲突时按 SKILL.md 的优先级解决。若同一优先级的两个规则无法同时满足，并且会实质改变结果，才需要用户决定。

## 跳过 Task Pilot 深入介入的情况

以下情况通常直接执行即可：

- 单一、明确、低影响的修改；
- 简单转换、解释、格式调整；
- 已有流程已经完整覆盖且没有状态/边界风险；
- Task Pilot 的进一步分析不会改变结果。

即使跳过深入介入，仍应遵守不扩大范围、不破坏已确认结果的基本边界。
