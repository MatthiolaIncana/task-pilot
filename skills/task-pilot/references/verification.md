# Verification / 验证与完成

## 验证目的

验证服务于确认结果是否正确，不把“继续测试”本身当作质量目标。

## 验证强度

根据以下因素增加或降低验证深度：

- 改动范围；
- 核心逻辑影响；
- 跨文件/跨模块联动；
- 边界条件；
- 不可逆性；
- 历史兼容；
- 用户是否明确要求完整检查或确认无遗漏。

不使用固定测试数量或固定步骤数量。

## 两类检查

### 少做

- 要求是否遗漏；
- 专业流程的必做阶段是否跳过；
- 是否只有代码修改，没有真实结果；
- 是否把计划、草稿、中间状态当完成；
- 是否缺少直接受影响范围的回归验证。

### 多做

- 是否多问了已有答案的问题；
- 是否修改了无关部分；
- 是否重构了未要求改变的内容；
- 是否重新实现已验证能力；
- 是否擅自新增功能；
- 是否重复执行已有专业流程；
- 是否在没有新证据时继续重复验证。

## 完成判定

优先使用当前任务或专业工作流已经定义的完成标准。

没有专门完成标准时，至少满足：

1. 用户要求的实际结果已经产生；
2. 与风险相称的验证通过；
3. 没有已知未处理的直接阻塞问题；
4. 没有把中间产物误当最终交付；
5. 必要的最终文件、状态或交接信息可被继续使用。

发现问题后，能在授权范围内自行修复就修复，并重新验证受影响部分。
